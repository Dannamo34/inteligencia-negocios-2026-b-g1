# Week 03 - Business Intelligence

## 1. Classification of Real Systems

### System 1: Student Enrollment System

**Type: OLTP (Online Transaction Processing)**

The student enrollment system is an OLTP system because it is used to register and update students' daily academic operations. This system handles processes such as student enrollment, course registration, academic information updates, and payment registration.

Its main objective is to process transactions quickly and keep the university's operational information up to date.

### System 2: Academic Performance Management Report

**Type: OLAP (Online Analytical Processing)**

The academic performance management report is an OLAP system because it is focused on analyzing historical and aggregated information. It allows users to analyze information about grades, courses, academic programs, academic periods, and student performance.

Its main objective is to facilitate data analysis and support decision-making rather than process daily transactions.

---

## 2. Analytical Question

For the academic performance analysis system, the following question is proposed:

**What has been the evolution of the overall average grades by academic program over the last 5 years, and which programs have the highest and lowest performance?**

This question requires analyzing historical information, performing aggregated calculations, and comparing different academic periods and programs. Therefore, it would not be convenient to answer it directly using the operational enrollment database.

---

## 3. Why Use a Data Warehouse?

Moving this data to a Data Warehouse improves the analysis for several reasons:

### Performance

It allows complex queries, calculations, and aggregations to be performed without affecting the operation of the university's enrollment system.

### Structure

Data from different sources can be integrated and organized into a structure specifically designed for analysis.

### Historical Data

A Data Warehouse allows information from different academic periods to be preserved, making it easier to compare results and analyze trends over time.

In this way, the university can access historical information more quickly and in a more organized manner to support decision-making.

---

## 4. OLTP → ETL → Data Warehouse → Report Flow

The proposed flow for this case is:

**OLTP → ETL → Data Warehouse → Report / Dashboard**

### OLTP - Operational System

It contains the data generated by the university's daily operations, such as:

- Student enrollment.
- Course registration.
- Grades.
- Academic programs.
- Academic periods.
- Student information.

### ETL - Extract, Transform, and Load

The data goes through the following process:

1. **Extracted** from the OLTP system.
2. **Transformed** through cleaning, validation, and organization.
3. **Loaded** into the Data Warehouse.

### Data Warehouse

It stores integrated, organized, and historical data to facilitate queries and analysis.

It can preserve information from several years and allow comparisons between academic programs, courses, and academic periods.

### Report / Dashboard

Finally, analytics tools such as Power BI can query the Data Warehouse to generate reports and dashboards.

These reports can show:

- Average academic performance by program.
- Performance evolution by year.
- Courses with the highest number of failed students.
- Comparisons between academic periods.
- Academic performance trends.
